{% comment %} `{% comment %}`, and never the brace-hash form for a comment this long. Django's lexer matches that form with a non-greedy `.` and **no** `re.DOTALL`, so one spanning more than a single line is never recognised as a comment at all: every line of it is emitted as text — here, directly under the school name, on the card a family reads. This block and the attendance one below both did exactly that. Single-line brace-hash comments are fine; this file simply does not use them, so that the rule needs no judgement to follow. `card.is_revised`, which task 8 makes the only source of this word — not `card.version > 1` spelled out again here. The two agree today, because that is exactly what `ReleasedCard.is_revised` computes; stating the rule a second time in a template is how they stop agreeing, and the model's docstring names the case it is protecting (a child placed into a term after release gets her first card through the revision path, at version 1, and must not be told it corrects something she never received). Whichever name is used, the failure mode is silence: a missing attribute resolves to the invalid-variable default, so this branch goes quietly unreachable and a reissued card prints identical to the one already in a parent's hand. That is what happened to the first draft of this page, and it is why the tests assert both the badge and its absence. {% endcomment %} {% if card.is_revised %}
