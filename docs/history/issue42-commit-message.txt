Where a paper prints is the school's answer, not the alphabet's

Closes #42, which was `must-fix-before-release` and stayed that way: the column
order is frozen onto each card at release, so a wrong order cannot be corrected
on cards already in a parent's hand.

`Assessment` had no field saying where it printed. `Meta.ordering` ended in
`name` — alphabetical, so a term's papers sorted "Exam, First CA, Second CA",
which is neither the order they were sat nor the order a Nigerian report card
prints. `cards._assessments_for()` worked around it by sorting on
`(subject name, id)` — creation order — and said in its own docstring that this
was a guess.

`Assessment.position` replaces the guess: explicit, smallest first, and
deliberately **not** unique per `(term, subject)` — the same shape and the same
argument as `results.Trait.position`, where a unique constraint would make the
ordinary edit, swapping two papers round, impossible without a temporary value.
`Meta.ordering` gains it ahead of `name` and ends in `id` so the order is total.

## The backfill writes down the order rather than improving it

`0003` numbers existing papers by creation order, in tens.

Cards already released were frozen under creation order. A backfill that
reshuffled would make cards released tomorrow disagree with cards sent home last
term — same child, same term, different columns — and nothing could reconcile
them, because the frozen order is exactly what cannot be corrected after the
fact.

A name heuristic ("First CA" first, "Exam" last) was considered and rejected. It
is right only for the names it recognises and silently reorders everything else:
"Test 1", "CA1", "Mid-Term", a label in a language it does not read. That is not
a hypothetical class of data, it is the ordinary contents of the column, and the
failure is invisible until a parent compares two cards.

Tens rather than ones so a paper can be inserted between two others without
renumbering. Schools set the order they want from here on; this migration only
stops the old one being lost in the move.

## The tests

Seven, across two schools, over rows staged into the shape `0003` finds — the
column freshly added, every position still at its default.

The backfill is the migration's own function, imported from it rather than
copied, and called with the **historical registry**: models rebuilt from
migration state, which is what Django hands a `RunPython`. Handing it
`django.apps` would test different code, and different in the direction that
hides bugs.

**Papers are created "First CA", "Second CA", "Exam"** — an order alphabetical
sorting cannot reproduce. In the base setup's first term the two happen to
agree, so these go in a term of their own; a test that cannot distinguish
creation order from alphabetical order proves nothing here, and
`test_the_order_is_the_one_sat_and_not_the_alphabetical_one` is what says so out
loud.

`test_the_staging_is_real` is the guard against the case that hid `0017`'s
deploy-stopper: an empty table makes the backfill a silent no-op and every other
assertion vacuous.

## The test that nearly proved nothing

The frozen-card test first read a released card's rows, ran the backfill, and
read them again. It passed, and it would have passed against any backfill at
all: the migration writes to `Assessment` and never to a released card, so those
rows could not have differed. A control that reshuffles alphabetically left it
green, which is how it was caught.

It now releases, backfills, then **reissues**, and compares version 2's columns
against version 1's. That is the failure this whole decision exists to prevent,
stated as an assertion: two versions of one child's card for one term,
disagreeing about which paper is the first column. `ReleasedAssessmentScore.
position` is an ordinal from `enumerate()`, not a copy of `Assessment.position`,
so it follows the ordering — a reshuffling backfill puts different names against
the same numbers, and the comparison fails.

## Verification

| Run | Result |
| --- | --- |
| `makemigrations --check --dry-run` | `No changes detected`, exit 0 |
| Seven tests, two schools | `Ran 7 tests in 26.146s`, `OK`, `EXIT=0` |
| **Control A** — backfill made a no-op | `FAILED (failures=4)`, `EXIT=1` |
| **Control B** — backfill numbers alphabetically | `FAILED (failures=6)`, `EXIT=1` |

Control A and control B are a matched pair. Both break the numbering, so both
fail the four tests that assert it. B additionally reshuffles, and that is the
whole difference between them — so the tests only B fails are exactly the tests
that detect a reshuffle:
`test_the_printed_order_is_byte_identical_across_the_backfill` and
`test_a_card_frozen_after_the_backfill_agrees_with_one_frozen_before`. Before
the frozen-card test was rewritten, only the first of those separated them.
